# Вариант C: максимальная скрытность (v2rayN)

Этот документ описывает рекомендуемую конфигурацию v2rayN для обхода блокировок и DPI в РФ.
Вариант C использует Xray с REALITY, имитацию TLS-отпечатка Chrome (uTLS), транспорт XHTTP с паддингом,
фрагментацию ClientHello, DoH/fake-ip DNS и правила маршрутизации «RU напрямую, остальное через прокси».

## 0. Предварительные требования

- Ядро: **Xray** (для REALITY/XHTTP) или **sing-box** (для Hysteria2/TUIC).
- Актуальная версия v2rayN (ветка `master`).
- VPS/сервер с Xray, настроенный на REALITY (см. документацию XTLS/Xray-core).
- (Опционально) резервные серверы в разных юрисдикциях.

## 1. Добавление сервера VLESS + REALITY

1. Серверы → Добавить → VLESS.
2. Заполните адрес, порт, UUID, Flow (`xtls-rprx-vision`).
3. Безопасность потока: **reality**.
4. SNI: укажите домен-«маску» (реальный HTTPS-сайт, который разрешён и доступен).
5. Public Key / Short ID: из конфига сервера.
6. Fingerprint (uTLS): **chrome** (по умолчанию в этой сборке уже `chrome`).

> Важно: REALITY несовместим с фрагментацией `tlshello` — клиент автоматически заменяет её на `1-3` пакеты.

## 2. Транспорт XHTTP (максимальная мимикрия под HTTPS)

1. В настройках сервера выберите сеть **xhttp**.
2. Mode: `auto` (или `stream-up`/`stream-down` при необходимости).
3. Path/Host: согласуйте с сервером (часто `/` или случайный путь).
4. Extra (JSON): при необходимости добавьте `downloadSettings` для раздельного канала скачивания.
5. Паддинг включается через `XhttpExtra` (см. документацию Xray XHTTP).

XHTTP выглядит как обычный HTTPS-трафик и лучше обходит DPI, чем WebSocket.

## 3. Фрагментация (anti-SNI-DPI)

В настройках (CoreBasic) включены по умолчанию:
- **EnableFragment** — разбиение TLS ClientHello на несколько пакетов (сбивает SNI-фильтрацию).
- При обновлении с оригинального v2rayN один раз (при первом запуске этой сборки) включается фрагментация, а пустые uTLS-отпечаток и User-Agent заменяются на `chrome`. Если потом выключить фрагментацию, при следующих запусках она не включится снова.
- Для «финальной» фрагментации включите **EnableFinalFragment** (добавляет freedom-аутбаунд с dialerProxy; чуть выше задержка, но сильнее скрывает трафик).

## 4. DNS (DoH + fake-ip)

По умолчанию в этой сборке:
- Прямой (direct) DNS и Bootstrap DNS: Яндекс `77.88.8.8` — им резолвятся только домены, идущие напрямую.
- Удалённый (remote) DNS: Cloudflare DoH, запросы идут через прокси.
- **fake-ip по умолчанию выключен** — включите его вручную в настройках DNS, если нужен (диапазон `198.18.0.0/15`).

Рекомендации:
- Для удалённого DNS используйте DoH (Cloudflare, Google, Quad9 или свой) — только через прокси.
- Не отправляйте `8.8.8.8`/`1.1.1.1` напрямую: открытый DNS к зарубежным резолверам подменяется DPI и даёт утечку.
- Включите «ServeStale» и «ParallelQuery» при нестабильной сети.
- Проверяйте утечки DNS (dnsleaktest.com).

## 5. Маршрутизация

- DomainStrategy: `IPIfNonMatch`. При `AsIs` правила по IP (`geoip:ru`) не срабатывают для запросов по домену. Пресет RU direct уже задаёт `IPIfNonMatch` сам.
- Правила:
  - RU-домены/IP → **Direct** (чтобы не гонять локальный трафик через прокси).
  - Реклама/трекеры → **Block**.
  - Остальное → **Proxy**.
- Финальное правило: `tcp,udp → Proxy` (или balancer при нескольких серверах).
- В этой сборке пресет **«Обход России (RU direct)»** выбран по умолчанию: зоны `.ru`/`.su`/`.рф`, `geosite:category-ru` и `geoip:ru` идут напрямую, остальное — через прокси.
- При новой установке источники geo-файлов, наборов правил sing-box и шаблона маршрутизации сразу указывают на проект runetfreedom (как после выбора пресета **Россия**). При первом запуске ничего не скачивается: работает встроенный пресет RU direct и встроенный DNS (Яндекс), а списки runetfreedom подтягиваются при обновлении geo-файлов и при импорте расширенных правил маршрутизации.
- Для более полных списков (в т.ч. заблокированных ресурсов) используйте меню региональных пресетов → **Россия**: подтягиваются geo-файлы, шаблон маршрутизации и DNS из проекта runetfreedom.
- При обновлении с оригинального v2rayN пресет RU direct добавляется в список один раз (без смены активного правила); если его удалить, он не появится снова.

## 6. Несколько серверов и автовыбор

- Добавьте 2–3 сервера в разных юрисдикциях.
- Включите балансировщик (leastPing) и health-checks.
- Профили: «Скорость» (Hysteria2/TUIC) и «Скрытность» (REALITY+XHTTP+фрагментация).

## 7. Проверка

- `curl https://ifconfig.me` — IP должен быть серверным.
- `dnsleaktest.com` — без утечек.
- Задержка/скорость — через встроенный тест.
- Логи соединений — включите Loglevel `warning`/`info` для диагностики.

## 8. Анти-DPI чек-лист

- [ ] uTLS fingerprint = chrome/firefox (не пустой).
- [ ] StreamSecurity = reality (не tls без SNI).
- [ ] Фрагментация включена.
- [ ] Удалённый DNS через DoH (через прокси); fake-ip — по желанию.
- [ ] Нет утечек WebRTC/DNS.
- [ ] SNI указывает на реальный разрешённый домен.
- [ ] XHTTP mode не `auto`? — `auto` ок, но для стабильности можно зафиксировать.

## 9. Устранение неполадок

- **Соединение рвётся:** проверьте SNI/PublicKey/ShortId, попробуйте другой маскирующий домен.
- **Низкая скорость:** переключитесь на Hysteria2/TUIC (sing-box) или уменьшите паддинг.
- **DPI всё равно ловит:** включите EnableFinalFragment, попробуйте XHTTP вместо WS, смените fingerprint.
- **DNS не резолвится:** проверьте bootstrap DNS и доступность DoH.

## 10. Профили «Скорость / Скрытность»

В v2rayN можно держать два набора серверов и переключаться между ними:

- **Скорость:** Hysteria2/TUIC (sing-box) или VLESS+XHTTP с одним сервером, без фрагментации.
- **Скрытность:** VLESS+REALITY + chrome uTLS + XHTTP + фрагментация + RU-direct пресет.

Рекомендуется:
- Создать отдельные группы (Policy Group) для каждого профиля с `MultipleLoad = LeastPing`.
- Включать health-checks (таймаут 10–20 с) для автовыбора лучшего сервера.
- Переключать активный профиль в зависимости от сети (дома / мобильный интернет / публичный Wi-Fi).

## 11. Health-checks и автовыбор

- В настройках группы серверов включите `LeastPing` — ядро будет выбирать сервер с минимальной задержкой.
- Health-check URL: используйте лёгкий эндпоинт (например, `https://www.gstatic.com/generate_204`).
- Таймаут: 10–20 с; при нестабильной сети увеличьте.
- Автовыбор срабатывает при недоступности текущего сервера.

## 12. CDN-fronting (опционально)

- Используйте XHTTP с `Host` из разрешённого домена и `Path` согласованный с сервером.
- Ротация CDN-провайдеров снижает риск блокировки по IP.
- Избегайте публичных списков «бесплатных» CDN — они быстро блокируются.

## 13. Ограничения

- Нет «серебряной пули»: DPI эволюционирует, конфиги нужно обновлять.
- Используйте только легитимные VPS/CDN.
- Соблюдайте локальное законодательство.
